Motion planning in control-point space

Planning an arm motion means finding a path through obstacles while accounting for joint and motion limits. Planigo represents the whole motion as a cubic B-spline in joint space and optimizes its free control points on the GPU using mixture-model information-geometric optimization (MGIGO). After a single solve, analytic retiming adjusts the trajectory duration without changing its geometry.

This page presents the offline, full-horizon planner: a complete trajectory from a fixed start to a selected inverse-kinematics goal. The demonstrations below replay precomputed plans; the browser does not run the optimizer.

Method

From a compact curve to a complete motion

01 Represent the motion

Twelve control points describe a continuous joint-space curve. Six free, seven-dimensional controls are optimized; the endpoints remain fixed.

Cubic B-spline · 42 optimization variables

02 Optimize on the GPU

MGIGO samples candidate controls, evaluates their costs at 32 waypoints in parallel, and updates a Gaussian mixture for each free-control block.

300 iterations · 300 samples per iteration

03 Evaluate the complete motion

After analytic retiming, evaluate the complete trajectory for goal accuracy, collisions, joint limits and dynamics. The number of evaluation samples grows with the final physical duration, including both endpoints.

N = ceil(T / 0.025 s) + 1 · 101 samples for 2.5 s

Current full-horizon method, updated 8 October 2026. Optimization uses 32 waypoints; final evaluation uses a maximum 0.025 s interval. Method illustrations are schematic. Control points live in seven-dimensional joint space, not on the Cartesian end-effector path.

What is being compared

Planigo performs one MGIGO solve followed by analytic retiming. cuRobo Optimization makes one IK + trajectory-optimization attempt using particle optimization and L-BFGS, with graph fallback disabled.

Both use canonical robot and scene inputs. Native IK, checker approximations, parameterization, seeding and budgets still differ; this compares configured planning pipelines, not equal-budget optimizers.

Reading the results

Planigo passes 92/100 inverted-box tasks; cuRobo Optimization passes 27/100. The under-table group remains difficult: Planigo 8/100, cuRobo 26/100. Planigo’s CPU ESDF construction median is 77.55 ms.

Native and shared success

cuRobo reports 651/800 native successes; 615/800 pass the shared acceptance policy. Optimization denotes cuRobo’s particle/L-BFGS mode, distinct from Schulman et al.’s TrajOpt algorithm.

Experimental setup & success criteria Reproducibility notes
Hardware & schedule
RTX 5060 8GB · Ryzen 7 7700 · Release · sm_120 · CUDA 13.2. Isolated planner processes run sequentially, with one warmup task per scene group. Desktop graphics remained active. The planner order changes across seeds.
Planigo
300 iterations; B=300, B0=100, T0=151; step 0.35; std 0.25 rad. Twelve cubic controls, six free controls, 32 cost waypoints. Solve at 2.5 s, analytically retime with 1.05 margin within [1,5] s. Strict fixed-goal IK; explicit session pool reuses allocations and resets task state. Both planners reset the batch seed before every task.
cuRobo
Version 0.8.0.post1.dev42, checkout 8e734f3. 32 IK seeds, four trajectory-optimization seeds, native B-spline model, CUDA graphs enabled. One attempt, graph fallback disabled. Native goal tolerances are aligned to the common position and quaternion thresholds.
Python & CPU evaluation
Python 3.11.14, NumPy 2.4.6; Robometrics C++ ESDF built with GNU 11.4.0, Release and pybind11 3.1.0. Single-thread C++ map construction runs on the CPU. JAX evaluation runs on CPU; OMP, OpenBLAS and MKL use one thread.
Shared evaluation
Canonical 61-sphere Franka model, 694 self-collision pairs; canonical OBB scene geometry; 0.02 m ESDF voxels. Position error ≤ 0.01 m; quaternion error 1 − |q·q*| ≤ 0.001. Environment clearance ≥ 0.01 m, self clearance ≥ 0; OOB, joint, velocity, acceleration and jerk checks. Acceleration ≤ 15 rad/s²; jerk ≤ 500 rad/s³.
Sampling & timing limits
Endpoint-inclusive uniform physical grids with maximum 0.025 s interval. IGO uses analytic B-spline derivatives; cuRobo uses quintic Hermite reconstruction of native q/dq/ddq. Pipeline time may include JITs for unseen evaluation shapes. The headline reports optimization only; compare planners using the broader planning column. Discrete checks do not establish continuous safety.

Scope and limitations

Compact control-point optimization and analytic retiming make the planning pipeline straightforward to inspect. The current implementation nevertheless uses soft ranking costs and discrete collision evaluation. Independently selected block means are not guaranteed to form a feasible joint solution.

There is no swept-volume collision check, mandatory execution gate or validated fallback controller. These are offline research results, not evidence of safe real-robot execution. The current comparison uses one dataset, fixed configurations and seed42. Native IK, checker approximations and budgets limit conclusions about optimizer quality alone.
