Motion planning in control-point space

Planning an arm motion means finding a path through obstacles while accounting for joint and motion limits. Planigo represents the whole motion as a cubic B-spline in joint space and optimizes its free control points on the GPU using mixture-model information-geometric optimization (MGIGO). After a single solve, analytic retiming adjusts the trajectory duration without changing its geometry.

This page presents the offline, full-horizon planner: a complete trajectory from a fixed start to a selected inverse-kinematics goal. The demonstrations below replay precomputed plans; the browser does not run the optimizer.

Method

From a compact curve to a complete motion

01 Represent the motion

Twelve control points describe a continuous joint-space curve. Six free, seven-dimensional controls are optimized; the endpoints remain fixed.

Cubic B-spline · 42 optimization variables

02 Optimize on the GPU

MGIGO samples candidate controls, evaluates their costs at 32 waypoints in parallel, and updates a Gaussian mixture for each free-control block.

300 iterations · 300 samples per iteration

03 Evaluate the complete motion

After analytic retiming, evaluate the complete trajectory for goal accuracy, collisions, joint limits and dynamics. The number of evaluation samples grows with the final physical duration, including both endpoints.

N = ceil(T / 0.025 s) + 1 · 101 samples for 2.5 s

Current full-horizon method, updated 8 October 2026. Optimization uses 32 waypoints; final evaluation uses a maximum 0.025 s interval. Method illustrations are schematic. Control points live in seven-dimensional joint space, not on the Cartesian end-effector path.

What is being compared

Planigo performs one MGIGO solve followed by analytic retiming. cuRobo Optimization makes one IK + trajectory-optimization attempt using particle optimization and L-BFGS, with graph fallback disabled; cuRobo Full permits up to five attempts with graph seeding enabled from attempt 1.

Native IK, collision representations and search budgets differ. Planigo uses an analytic ESDF and a fixed IK endpoint; cuRobo uses its native Franka model and OBB world. This is a comparison of configured planning pipelines, not an equal-budget optimizer ablation.

Reading the results

The aggregate success gap is concentrated in the inverted-box group: Planigo passes 94/100, cuRobo Full 28/100. cuRobo Full passes more cage and under-table tasks. Differences in native IK and geometry need to be audited before attributing these gaps to the optimizers.

“Optimization” names the cuRobo pipeline mode, rather than the separate TrajOpt algorithm of Schulman et al. See cuRobo’s technical report and the TrajOpt documentation.

Native and shared success

cuRobo's native success counts are cuRobo · Optimization: 651/800; cuRobo · Full: 655/800. The tables use the shared evaluator instead, with identical goal, clearance, joint and dynamics thresholds.

Hardware & schedule
RTX 4060 Laptop GPU · Release · sm_89. Three isolated processes, run sequentially after warmup. One measured pass per mode; timing percentiles are across tasks, not repeated-run confidence intervals. Desktop graphics remained active.
Planigo
300 iterations; B=300, B0=100, T0=151; step 0.35; std 0.25 rad. Twelve cubic controls, six free controls, 61 cost waypoints. Solve at 2.5 s, then analytically retime with 1.05 margin within [1,5] s. Seed 42 + problem index.
cuRobo
Version 0.8.0.post1.dev42, checkout 8e734f3. 32 IK seeds, 4 trajectory-optimization seeds, native B-spline trajectory model, CUDA graphs enabled. Seed 42 reset per task. Native position / orientation tolerances: 0.01 m / 0.05 rad. Optimization collision activation distance: 0.02 m. This configuration returns 2.0 s motions. No planner was tuned on this comparison.
Shared evaluation
57-sphere Franka model; 0.02 m ESDF voxels; goal position error ≤ 0.01 m; quaternion error 1 − |q·q*| ≤ 0.001 (dimensionless). Environment clearance ≥ 0.01 m, self clearance ≥ 0; OOB, joint, velocity, acceleration and jerk checks. Acceleration limit 15 rad/s²; jerk limit 500 rad/s³.
Sampling & timing limits
Maximum 0.025 s interval. Planigo and cuRobo use distinct time grids, so this is discrete evaluation, not a swept-volume guarantee. Planigo planning includes per-task session creation and ESDF upload; cuRobo reuses a warmed planner and its world update is counted in pipeline time. Pipeline timing includes first JITs for unseen evaluation shapes. The headline is Planigo optimization only; compare planners using the broader planning column.
CUDA event cross-check
Planigo optimization CUDA-event median / P90: 157.7 / 168.0 ms. These are scoped GPU timeline measurements, not sums of kernel durations. Displayed comparison times are synchronized host elapsed.

Scope and limitations

Compact control-point optimization and analytic retiming make the planning pipeline straightforward to inspect. The current implementation nevertheless uses soft ranking costs and discrete collision evaluation. Independently selected block means are not guaranteed to form a feasible joint solution.

There is no swept-volume collision check, mandatory execution gate or validated fallback controller. These are offline research results, not evidence of safe real-robot execution. The comparison uses one dataset, fixed configurations and one measured pass per mode. Different internal robot and collision models limit conclusions about optimizer quality alone.
